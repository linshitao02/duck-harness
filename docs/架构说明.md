# 架构

浏览器或桌面壳只负责会话列表、消息流和连接面板。业务在 FastAPI 里。

打开后先登录。登录状态会记住，退出才需要重新登录。会话、上传文件和设置按用户分开。

一次发送会把用户消息写入 SQLite，再进入工具循环。`.env` 里如果写了 MySQL 并且连得上，会改用 MySQL。把当前会话里仍标记为“在上下文中”的消息、长期记忆、技能目录和任务交给模型。模型如果返回工具调用，后端就在本机执行，把结果存成 tool 消息，然后再问一次模型，直到它给出正文，或你停掉这一轮。流式事件用 SSE 推回页面。设置里保存的 DeepSeek 密钥入库前加密，调用模型时再解密。

新会话的开场提问在这个循环之外，最多两轮选项。你直接打字发消息，提问就结束。群聊也在循环之外：房间按 `@`、交接和私聊决定下一个开口的成员，每个成员仍是自己的会话。

DeepSeek 和 Ollama 都走各自的 OpenAI 兼容接口。DeepSeek 用 `https://api.deepseek.com/chat/completions`，Ollama 用本机 `http://127.0.0.1:11434/v1/chat/completions`。

权限有五种。`auto` 直接执行。`plan` 只能查看，并可以把方案写进计划文件。`ask` 在修改类工具执行前等页面上的允许或拒绝。`edits` 改文件不用再问，命令仍要确认。`dontAsk` 把该询问的操作直接拒绝。密钥文件和少数破坏性命令即使在自动模式下也会被拦住。

删掉会话时，这次上传的文件和只属于这次对话的撤销副本会一起清掉。工作区里的项目文件和长期记忆还留着。服务启动时也会扫掉已经没有对应会话的上传和撤销记录。

工作区默认是本仓库目录。终端是 PowerShell，文件工具可以读文本、Jupyter、PDF 和 Word，也可以生成 docx 附件。MCP 使用官方的 stdio 帧协议。表在启动时创建，缺的列也会补上。
